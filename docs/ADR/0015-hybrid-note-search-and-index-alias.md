# ADR-0015. Гибридный поиск заметок: RRF поверх SQL-ранжеров, алиас вместо перестройки

Дата: 2026-09-06. Статус: принят. Реализация: `knowledge/notes.py` (`search_hybrid`),
`knowledge/ranking.py` (BM25/RRF/rerank), миграция `0007_notes_search_alias`, флаг
`notes.hybrid_search`, гейт `tests/test_evals_gates.py`.

## Контекст

Поиск был «вектор, иначе текст»: два сильных ранжера, из которых в бою работает один.
Текстовый слепнет на перифразе («как перестать платить проценты» ≠ «ипотека: досрочное
погашение»), векторный — на точных совпадениях (номера, имена файлов) и на шумах
«соседних по смыслу» заметок. Плюс перестройка индекса historically означала либо
LOCK на живой таблице, либо окно «поиск молчит».

## Решение

1. **Ранжеры живут в SQL, слияние — в процессе.** `ts_rank` и pgvector-`<=>` отдают
   упорядоченные списки id (по `pool = max(limit*4, 20)`); `fuse_rrf(k=60)` сравнивает
   только места — скорости разных природ несопоставимы и не участвуют в решении.
   Порог вектора 0.2 сохранён: «чуть похож» — не находка.
2. **Дешёвый rerank на вершине.** `LexicalReranker` (покрытие запроса + title- hits +
   свежесть) переупорядочивает top-pool. Это не «вторая модель»: линейный скор
   объясним владельцу, детерминирован и работает при lie-down провайдера. Модельный
   rerank — следующий шаг и включается явно, потому что платный.
3. **Алиас вместо rebuild.** `index_version` на строке + `knowledge.index_state` +
   вьюха `knowledge.notes_search`: поиск читает вьюху; переиндексация поднимает версии
   строк пачками, «применение» — один UPDATE состояния, откат — UPDATE обратно.
   Строки старой версии не удаляются — они перестают попадать в активную вьюху.
4. **ANN — потом, и только с бюджетом.** Векторный ANN (HNSW/IVFFlat) не включён: на
   объёме личных заметок (~10⁴) точный косинус быстрее бюджета «p95 < 150 мс» и точнее
   любого approximate. Условие пересмотра: recall@10 просадка < 1% и latency-бюджет
   соблюдены на живом объёме, а не на глаз.
5. **Флаг и золотые данные.** Право на гибрид даёт `notes.hybrid_search` (перцентиль по
   actor, `decision_records` фиксирует оценку — A/B пересчитываем). CI-гейт: средний
   nDCG@5 по `evals/search_ranking_v1.jsonl` ≥ 0.94 и «fusion вытягивает lexical-gap» —
   смена скоринга без замера не мержится.

## Последствия

- `search()` остаётся контрактом деградации: нет вьюхи/БД/эмбеддингов — текстовый путь
  работает ровно как раньше (принцип 5). `search_hybrid` при любом сбое алиаса
  возвращается в `search()`, а не в исключение.
- TRGM-индексы (0007, `CONCURRENTLY`) ускоряют будущий fuzzy-слой; `LIKE`-фолбэк
  сохранён и с ними — при недоступном pg_trgm гибрид не «полурегистрируется».
- Откат релиза не откатывает переиндексированные строки (колонка и состояние живут и в
  downgrade): данные пережитого rollback — сознательный выбор contract-фазы (F10).
