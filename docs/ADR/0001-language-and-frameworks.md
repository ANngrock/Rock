# ADR-0001. Язык и фреймворки

- Статус: принят (шаг 1)
- Дата: 2026-09-04

## Контекст
Один владелец, один разработчик, нагрузка «много маленьких запросов + LLM-вызовы + фоновые задачи».
Нужен язык с сильной типизацией, зрелыми async-драйверами и дешёвой отладкой.

## Решение
Python **3.12** как целевой (reference) рантайм; `requires-python >= 3.11` — чтобы каркас проверялся
и на более старом интерпретаторе (в песочнице CI/dev нет 3.12, тесты обязаны проходить на обоих).

- `aiogram 3` — async-Telegram, хендлеры + outer-middleware (whitelist);
- `SQLAlchemy 2 (async)` + `asyncpg` — доступ к Postgres; ORM-слой намеренно не введён: шаг 1 живёт
  на `text()`-запросах, схема = контракт домена, миграции пишутся руками;
- `Pydantic v2` + `pydantic-settings` — схемы аргументов инструментов и конфигурация;
- `FastAPI` — **не** на шаге 1: появляется на шаге 9 вместе с mini-app API, до этого HTTP-сервер не нужен.

## Последствия
- (+) Один язык на всё (бот, БД, инструменты, парсеры), типы проверяются `mypy --strict`.
- (+) Сквозной async: нет «синхронных дыр» между ботом, БД и LLM.
- (−) `text()` вместо ORM — часть SQL приходится ревьюить руками; компенсируется интеграционными
  тестами на реальном Postgres и констрейнтами прямо в схеме.
- (−) Поддержка 3.11 как минимума ограничивает синтаксис (без PEP 695 и т. п.) — осознанно.
